# One degenerate message carried 443 identical empty tool calls — js executed all of them

Category: bug
Status: wontfix
Filed: 2026-08-14 (rewritten same day after session-log verification)
Component: `js/runtime.py` (tool dispatch), tool-call validation

## Verified mechanism (session 20260814T162102202806Z-2f0a5f428290e5ca)

Not a retry loop across turns. The log shows:

- ONE assistant message with a `tool_calls` array of **443 entries**
- `distinct_args = 1` — all identical, arguments **`{}`** (empty)
- All 443 ids are 32-char mixed-case alphanumeric — llama.cpp's
  `random_string()` format. Neither js nor the ai SDK mints ids (verified by
  grep). The server itself emitted 443 entries.
- Attribution: llama.cpp's incremental tool-call stream parser is the prime
  suspect — empty-args entries with fresh server ids = parser opening calls
  without attaching argument bodies. The MTP/speculative build shifts chunk
  boundaries, aggravating incremental parsing. The model was mid-coherent
  work; a model loop would repeat complete calls with args, not empties.
  Definitive proof needs yoda-side verbose generation logs or a repro.
- js dispatched **all 443**. Every result: `ERROR: path is required`
  (some with `<retry attempts_left=...>` decoration adding more tokens)
- 443 identical error results ballooned the transcript to ~97k tokens →
  context overflow → cascade into `.scratch/compact-overflow/issues/01`
  (detector missed llama.cpp phrasing, /compact could not fit either;
  session unrecoverable)

## Problems, in dispatch order

1. **No pre-dispatch schema validation.** `patch` requires a path; args `{}`
   is invalid on its face. An invalid call should fail cheap and once, not
   execute.
2. **No dedupe of identical calls within one message.** 443 × identical
   (name, args) should execute once and reuse the result — or reject the
   batch as degenerate.
3. **No sanity cap on the array.** A 443-entry tool_calls array from one
   message is not plausible work from any model. Cap (configurable, ~50) and
   reject the remainder with one message to the model.
4. **No collapse of identical results.** 443 copies of the same error is
   pure context poison. Consecutive identical tool results should collapse
   to first occurrence + "repeated N times".

Small local models make degenerate generations routine, not rare. The
harness is the only sane party in the loop; it must be the adult.

## Proposed fix (in order of payoff)

1. Dedupe identical (name, args) within a message: execute once, fan out the
   single result. One-screen change, kills 442/443 of the damage.
2. Reject calls that fail the tool's required-arg schema before dispatch.
3. Per-message tool_calls cap with a clear model-facing error.
4. Collapse consecutive identical results when appending to the transcript.

## Acceptance

Replay a synthetic assistant message with 200 identical empty patch calls:
one execution, one error in transcript, turn continues; context grows by
one result, not two hundred.

## Agent Brief

**Category:** bug
**Summary:** Normalize and bound malformed tool-call batches before they can
execute or enter persistent history.

**Current behavior:**
Every tool call in one assistant response is persisted and dispatched as-is.
Exact duplicates are not collapsed, arguments are not checked against the
tool's complete declared JSON schema before handler invocation, and the
per-message array has no size ceiling. A synthetic response containing 200
identical empty `patch` calls currently creates 200 dispatch records and 200
errors.

**Desired behavior:**
One assistant batch should become a bounded, protocol-valid set of calls before
persistence or execution. Exact duplicates should be represented once, invalid
arguments should fail before reaching a handler, and an implausibly large set
of distinct calls should be capped with one clear model-facing diagnostic. The
assistant call record and its tool-result records must remain a strict one-to-one
pair after normalization.

**Key interfaces:**
- Assistant tool-call batch normalization — identity is the resolved canonical
  tool name plus canonicalized argument object; the first call ID represents an
  exact-duplicate group
- `Tool` declarations — validation must honor the complete schema, including
  custom schemas with `oneOf`, nested requirements, and additional-property
  restrictions
- Per-message tool-call limits — a dedicated configurable ceiling should bound
  distinct calls independently of the turn's model/tool iteration ceiling
- Persistent and provider-facing history — both forms must contain the same
  normalized call IDs and exactly one result for every retained call

**Acceptance criteria:**
- [ ] A batch of 200 identical empty `patch` calls produces one retained call,
      no handler side effect, and one schema-error result
- [ ] The next model request accepts the normalized history under strict message
      integrity checks; no orphaned call or result is created
- [ ] A batch over the distinct-call ceiling executes no more than the configured
      limit and emits one concise diagnostic for the rejected remainder
- [ ] Valid nonduplicate parallel calls still all execute and their result order
      remains the model's original order
- [ ] Canonical tool aliases and semantically identical JSON argument formatting
      deduplicate consistently
- [ ] Telemetry reports the received count, retained count, duplicate count,
      invalid count, and capped count without emitting hundreds of duplicate
      events

**Out of scope:**
- Fixing llama.cpp's incremental tool-call parser
- Context-overflow recovery, which is tracked separately
- Deduplicating similar but nonidentical operations whose safety cannot be
  established from canonical name and arguments alone

## Triage Outcome

Closed as already implemented by commit `bc1c111` on `main`.

`run_turn_async()` now canonicalizes tool names and JSON argument objects,
collapses exact duplicates while retaining the first call ID, validates each
distinct call against the tool's complete published JSON Schema, and applies
the dedicated `limits.max_tool_calls_per_message` ceiling before either form of
assistant history is written. Invalid retained calls receive one schema-error
result without invoking the handler. Capped remainder calls produce one concise
model-facing diagnostic. One aggregate telemetry event records received,
retained, duplicate, invalid, and capped counts.

The 200-empty-`patch` regression retains one call/result pair, invokes the
handler zero times, and passes strict history validation on the next model
request. Alias/JSON-format deduplication and distinct-call capping have separate
coverage. The final offline suite passed 1,291 tests and lint passed.
