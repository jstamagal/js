# What `/help fset NAME` prints: each /fset entry's NAME alone on a line,
# then its help, indented four spaces. Lines starting with # are comments.
# A colour is #rrggbb, a palette slot 00-98, or $NAME of another colour;
# a|b takes the first that resolves. PALETTE_00..PALETTE_98 are the mIRC
# palette; every message's format is named after its js/messages.py entry.
# FORMAT and PALETTE below are not entries: they explain every format and
# every palette slot.

FORMAT
    Every message's format is named after its js/messages.py entry: /fset
    MODEL_SET shows it, /fset MODEL_SET text changes it. A format is
    literal text, colour codes, the banner glyph and holes. The event hands
    its format one line of text, split on single spaces into words numbered
    from 0. Every field but the last is one word; only the last may contain
    spaces. $0 to $9 is that word; $N- is word N through the end of the
    line; $* is the whole line. A format may use any word, in any order, or
    leave any out. A - right after $N reads as $N-: $N%C- is the word, then
    a dash. %Cnn draws what follows in palette slot nn, 00 to 98
    (see PALETTE); %C goes back to the terminal's own colour. %G is the
    banner glyph, the BANNER setting. %% is a %, $$ a $. Any other % or $
    code, a slot past 98, or a word the event does not pass is refused when
    the format is set. Example: %C04%G%C Unknown setting: %C04$0%C draws
    the glyph red, the words in the terminal's colour and the setting's
    name red. A message's default format is its text with $N for each
    field and $N- for the last, after %G and a space when it is a line
    where js reports its own state; js/fset draws a failure's glyph in
    slot 04 and a warning's in slot 07.

PALETTE
    nn in %Cnn, and a two-digit colour value, is a slot of the mIRC
    99-colour palette, PALETTE_00 to PALETTE_98, each a #rrggbb js sends as
    24-bit colour. 00 white, 01 black, 02 blue, 03 green, 04 red, 05 brown,
    06 purple, 07 orange, 08 yellow, 09 light green, 10 cyan, 11 light
    cyan, 12 light blue, 13 pink, 14 grey, 15 light grey; 16 to 87 are six
    rows of twelve hues, darkest first, and 88 to 98 a grey ramp from black
    to white. A theme changes what a slot looks like, so a format that names
    slot 04 for failures shows the theme's red.

REASONING_DISPLAY
    Reasoning display: 0 hidden; 1, the default, streams, then folds to
    `N tok reasoning` when the answer starts; 2 leave visible; 3 leave
    visible with the provider's token count. The count is the provider's or none.
    The reasoning_toggle key, Ctrl-O unless KEYBINDS_FILE moves it, folds
    and unfolds it in the async screen. Folding is the screen's: in js -p
    and the blocking REPL, 1 to 3 print the text and then the count line.
    Display only; session reasoning is always retained.

NET_DISPLAY
    Network display in the async screen: 0 nothing, 1 failures, 2 also
    Connecting/Connected lines and a response byte counter on the status bar
    until the first token, 3 also catalog refreshes and per-call stream
    stats. Retries and the line that gives up on them print at every level.

TOOLS_DISPLAY
    Tool exchange display: 0 nothing; 1 what matters: quiet calls fold into
    one row per tool, a command shows its output while it runs and one row
    after, a patch shows its diff, a failure its error; 2 every call with
    the first TOOLS_PREVIEW_LINES result lines; 3 every call whole. At 1 and
    2 in the async screen, the reasoning_toggle key, Ctrl-O, unfolds every
    folded row and preview to its whole form and folds it back. Under js -p
    nothing unfolds: quiet calls are a row each, hidden lines stay hidden,
    and a subagent run also gets a row when it starts. The
    session transcript keeps every call whole.

TOOLS_QUIET
    Tools whose calls TOOLS_DISPLAY 1 shows as one row and folds: a JSON
    list of tool names.

SHELL_QUIET
    Shell commands TOOLS_DISPLAY 1 treats as quiet, by first word or first
    two: a JSON list.

TOOLS_PREVIEW_LINES
    Lines of a result, a diff or a program shown before the rest is hidden
    at TOOLS_DISPLAY 1 and 2. On the screen the reasoning_toggle key, Ctrl-O,
    unfolds them; under js -p they stay hidden.

MARKDOWN
    Render assistant Markdown on a terminal: finished blocks are highlighted
    once, the open block stays live. Off writes the text as it arrives.
    Output that is not a terminal is always plain text.

RESUME_EXCHANGES
    Exchanges of a resumed session the REPL shows before its prompt, drawn
    as a turn draws them. 0 shows none.

TRACE
    Pretty-print the tool-call trace line as the model runs.

KERNEL_VERBOSITY
    How much of each kernel/toolbox call is rendered to your terminal.
    quiet: errors and interrupts only. normal: code, output, timing,
    namespace. verbose: stdout, stderr and display split out, plus kernel
    lifecycle and toolbox activity. Affects only what you see; the model
    always receives the full result.

KERNEL_LINES_MAX
    Line cap per section of the kernel's terminal render, so a 4000-line
    cell cannot scroll the screen away. Only the screen caps it, as a fold
    the reasoning_toggle key, Ctrl-O, unfolds to the whole render; anywhere
    else nothing can unfold it, so it prints whole. The hidden count is
    shown, and the model still gets the untrimmed output.

THEME
    The built-in theme: a palette, colours and formats under the entries set
    here. claude, crush, bitchx, github, paper or splash3.

HOST_COLOR
    This box's colour, for the prompt, the speaker marks and the status
    bar's accent. Empty leaves the theme's own.

CODE_STYLE
    The Pygments style code in answers and tool exchanges is highlighted in.

MARK_USER
    The operator's speaker mark, alone in column 0: the input prompt and
    each sent line.

MARK_AGENT
    The agent's speaker mark, alone in column 0 before its answer.

MARK_GAP
    Spaces between a speaker mark and its text; every row of the text starts
    there.

COLOR_BACKGROUND
    The screen's background in the async REPL. Empty leaves the terminal's
    own.

COLOR_TEXT
    Ordinary text js draws itself.

COLOR_DIM
    Metadata: arguments, line numbers, metrics.

COLOR_USER
    The operator's lines.

COLOR_USER_MARK
    The input prompt and the operator's speaker mark.

COLOR_AGENT
    The agent's colour, its mark's fallback.

COLOR_AGENT_MARK
    The agent's speaker mark.

COLOR_WARN
    Standard error in a tool exchange.

COLOR_ERROR
    A failed call's mark and its error text.

COLOR_OK
    A finished call's mark.

COLOR_TOOL
    A tool's name in a tool exchange.

COLOR_TOOL_OUTPUT
    A tool's output in a tool exchange.

COLOR_PANEL
    The background behind tool output and a tool's name.

COLOR_ACCENT
    Highlights: Markdown headings, links, list numbers.

COLOR_ADDED
    Added lines of a diff.

COLOR_REMOVED
    Removed lines of a diff.

COLOR_CODE
    Inline code in an answer, drawn on COLOR_PANEL.

COLOR_REASONING
    The model's reasoning text.

COLOR_SEPARATOR
    Rules and table borders.

COLOR_STATUS_BACKGROUND
    The status bar's background.

COLOR_STATUS_TEXT
    The status bar's text.

COLOR_STATUS_ACCENT
    The status bar's clock.
